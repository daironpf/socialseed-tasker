# Configuration Reference

Complete reference for all configuration options in Tasker.

---

## Configuration Resolution Order

Tasker resolves configuration in this priority order (highest to lowest):

1. **Environment Variables** — `TASKER_MODE`, `TASKER_API_URL`, etc.
2. **Configuration File** — `.agent/configs/tasker.yml`
3. **Built-in Defaults** — Hardcoded values

### Example Resolution

If you set:
```bash
export TASKER_MODE=api  # Environment variable
```

But also have in `.agent/configs/tasker.yml`:
```yaml
mode: direct  # Config file
```

**Result:** API mode is used (environment variable wins)

## Environment Variables

### Operation Mode

#### `TASKER_MODE`
- **Type:** String
- **Allowed Values:** `direct`, `api`
- **Default:** `direct`
- **Description:** Which backend to use
- **Example:**
  ```bash
  export TASKER_MODE=api
  ```

---

### Direct Mode (Neo4j Bolt)

These variables only apply when `TASKER_MODE=direct`.

#### `TASKER_NEO4J_URI`
- **Type:** String (URI)
- **Default:** `bolt://localhost:7687`
- **Description:** Neo4j Bolt connection string
- **Examples:**
  ```bash
  # Local development
  export TASKER_NEO4J_URI=bolt://localhost:7687
  
  # Remote with SSL
  export TASKER_NEO4J_URI=bolt+s://db.example.com:7687
  ```

#### `TASKER_NEO4J_USER`
- **Type:** String
- **Default:** `neo4j`
- **Description:** Neo4j username
- **Example:**
  ```bash
  export TASKER_NEO4J_USER=tasker-user
  ```

#### `TASKER_NEO4J_PASSWORD`
- **Type:** String (sensitive)
- **Default:** *(none - must be set)*
- **Description:** Neo4j password
- **Example:**
  ```bash
  export TASKER_NEO4J_PASSWORD=MySecurePassword123!
  ```

---

### API Mode (REST API)

These variables only apply when `TASKER_MODE=api`.

#### `TASKER_API_URL`
- **Type:** String (URL)
- **Default:** `http://localhost:8888`
- **Description:** FastAPI backend base URL
- **Examples:**
  ```bash
  # Local development
  export TASKER_API_URL=http://localhost:8888
  
  # Production
  export TASKER_API_URL=https://tasker-api.example.com
  ```

#### `TASKER_API_KEY`
- **Type:** String (Bearer token)
- **Default:** *(none - optional)*
- **Description:** Authentication token for API requests
- **Notes:** Only required if API enforces authentication
- **Example:**
  ```bash
  export TASKER_API_KEY=sk-prod-abc123def456ghi789
  ```

#### `TASKER_API_TIMEOUT`
- **Type:** Integer (seconds)
- **Default:** `10`
- **Description:** HTTP request timeout
- **Example:**
  ```bash
  export TASKER_API_TIMEOUT=30  # 30-second timeout
  ```

---

### Logging (Optional)

#### `TASKER_LOG_LEVEL`
- **Type:** String
- **Allowed Values:** `DEBUG`, `INFO`, `WARNING`, `ERROR`
- **Default:** `INFO`
- **Description:** Logging verbosity
- **Example:**
  ```bash
  export TASKER_LOG_LEVEL=DEBUG
  tasker component list  # Verbose output
  ```

#### `TASKER_LOG_FILE`
- **Type:** String (file path)
- **Default:** *(none - stdout only)*
- **Description:** Write logs to file instead of console
- **Example:**
  ```bash
  export TASKER_LOG_FILE=~/.tasker/logs/tasker.log
  ```

## Configuration File: `.agent/configs/tasker.yml`

### Location

Place at: `.agent/configs/tasker.yml` (relative to project root)

### Creating Configuration File

**Option 1: Interactive Setup**
```bash
tasker init
# Prompts you and creates the file
```

**Option 2: Manual Creation**
```bash
mkdir -p .agent/configs
cp src/socialseed_tasker/assets/templates/configs/tasker.yml.example .agent/configs/tasker.yml
nano .agent/configs/tasker.yml  # Edit your settings
```

### Direct Mode Configuration

```yaml
# Operation mode
mode: direct

# Neo4j connection
neo4j_uri: bolt://localhost:7687
neo4j_user: neo4j
neo4j_password: neoSocial

# Optional logging
log_level: INFO
```

### API Mode Configuration

```yaml
# Operation mode
mode: api

# API connection
api_url: http://localhost:8888
api_key: sk-your-key-here  # Optional
api_timeout: 10

# Optional logging
log_level: INFO
```

### Complete Example

```yaml
# Tasker Configuration
# Generated by: tasker init
# Last updated: 2026-05-25

# Operation mode: "direct" (Neo4j Bolt) or "api" (REST API)
mode: direct

# --- Direct Mode Settings ---
# Only used when mode = "direct"
neo4j_uri: bolt://localhost:7687
neo4j_user: neo4j
neo4j_password: neoSocial

# --- API Mode Settings ---
# Only used when mode = "api"
# Uncomment to use API mode
# api_url: http://localhost:8888
# api_key: your-api-key-here
# api_timeout: 10

# --- Logging (optional) ---
# log_level: INFO
# log_file: ~/.tasker/logs/tasker.log
```

## Configuration Scenarios

### Scenario 1: Local Development (Direct Mode)

**Use Case:** Developing locally with direct Neo4j access

**Setup:**
```bash
# .agent/configs/tasker.yml
mode: direct
neo4j_uri: bolt://localhost:7687
neo4j_user: neo4j
neo4j_password: neoSocial
```

**Or environment:**
```bash
export TASKER_MODE=direct
export TASKER_NEO4J_URI=bolt://localhost:7687
export TASKER_NEO4J_USER=neo4j
export TASKER_NEO4J_PASSWORD=neoSocial
```

### Scenario 2: Testing (API Mode with Local Server)

**Use Case:** Testing the CLI against the API server

**Setup:**
```bash
# .agent/configs/tasker.yml
mode: api
api_url: http://localhost:8888
# api_key: optional
api_timeout: 10
```

**Or environment:**
```bash
export TASKER_MODE=api
export TASKER_API_URL=http://localhost:8888
export TASKER_API_TIMEOUT=10
```

### Scenario 3: Production (API Mode with Remote Server)

**Use Case:** Deployed in production with centralized API

**Setup:**
```bash
# .agent/configs/tasker.yml
mode: api
api_url: https://tasker-api.example.com
api_key: sk-prod-abc123def456
api_timeout: 30
log_level: WARNING
```

**Or environment:**
```bash
export TASKER_MODE=api
export TASKER_API_URL=https://tasker-api.example.com
export TASKER_API_KEY=sk-prod-abc123def456
export TASKER_API_TIMEOUT=30
```

### Scenario 4: Remote Database (Direct Mode with SSH Tunnel)

**Use Case:** Connect to production database via secure tunnel

**Setup:**
```bash
# First, create SSH tunnel
ssh -L 7687:db.internal:7687 prod-server

# Then configure
export TASKER_MODE=direct
export TASKER_NEO4J_URI=bolt://localhost:7687
export TASKER_NEO4J_USER=prod-user
export TASKER_NEO4J_PASSWORD=prod-password
```

### Scenario 5: CI/CD (Testing Both Modes)

**Use Case:** Test suite that verifies both modes work

**GitHub Actions Example:**
```yaml
env:
  # Direct mode tests
  - name: Test Direct Mode
    env:
      TASKER_MODE: direct
      TASKER_NEO4J_URI: bolt://localhost:7687
      TASKER_NEO4J_USER: neo4j
      TASKER_NEO4J_PASSWORD: testpass
    run: pytest tests/integration/

  # API mode tests
  - name: Test API Mode
    env:
      TASKER_MODE: api
      TASKER_API_URL: http://localhost:8888
      TASKER_API_TIMEOUT: 10
    run: pytest tests/integration/
```

## Configuration Validation

### Check Current Configuration

```bash
# Show which configuration is active
python << 'EOF'
from socialseed_tasker.config.mode_config import DualModeConfig

cfg = DualModeConfig.load()
print(f"Mode: {cfg.mode}")
print(f"API URL: {cfg.api_url}")
print(f"Neo4j URI: {cfg.neo4j_uri}")
print(f"Loaded from: env → file → defaults")
EOF
```

### Test Connection

**Direct Mode:**
```bash
python << 'EOF'
from neo4j import GraphDatabase

driver = GraphDatabase.driver(
    "bolt://localhost:7687",
    auth=("neo4j", "neoSocial")
)
try:
    with driver.session() as session:
        result = session.run("RETURN 1 as test")
        print(f"✓ Connected! Result: {result.single()}")
finally:
    driver.close()
EOF
```

**API Mode:**
```bash
python << 'EOF'
import httpx

async def test_api():
    async with httpx.AsyncClient() as client:
        resp = await client.get("http://localhost:8888/health")
        print(f"Status: {resp.status_code}")
        print(f"✓ API OK: {resp.json()}")

import asyncio
asyncio.run(test_api())
EOF
```

## .gitignore Configuration

Protect sensitive configuration files:

```bash
# Add to .gitignore
.agent/configs/tasker.yml          # Don't commit your config
.agent/configs/.env                # Don't commit secrets
.env                               # Local environment
.env.local                         # Local overrides

# Optional: ignore logs
.agent/logs/
logs/
*.log
```

**Safe pattern:**
1. Commit `.agent/configs/tasker.yml.example` (without secrets)
2. Add `tasker.yml` to `.gitignore`
3. Each developer creates their own `tasker.yml` from the example

## Best Practices

### Security

1. **Never commit secrets**
   ```bash
   # DON'T commit this to Git
   echo "export TASKER_NEO4J_PASSWORD=mypassword" > .env
   
   # DO use .env.local and add to .gitignore
   echo ".env.local" >> .gitignore
   echo "export TASKER_NEO4J_PASSWORD=mypassword" > .env.local
   ```

2. **Use environment variables in CI/CD**
   ```bash
   # GitHub Actions
   - name: Run tests
     env:
      TASKER_NEO4J_PASSWORD: ${{ secrets.NEO4J_PASSWORD }}
     run: pytest
   ```

3. **Rotate API keys regularly**
   ```bash
   # Old key
   export TASKER_API_KEY=sk-old-key
   
   # After rotation
   export TASKER_API_KEY=sk-new-key
   ```

### Organization

1. **Use configuration files for teams**
   ```bash
   # Each team member has their own tasker.yml
   cp .agent/configs/tasker.yml.example .agent/configs/tasker.yml
   # Edit with your local settings
   ```

2. **Use environment variables for CI/CD**
   ```bash
   # Secrets stay in CI/CD platform, not in code
   ```

3. **Document your setup**
   ```bash
   # Create .agent/configs/SETUP.md for your team
   echo "# Local Setup\n\n\`\`\`bash\n..." > .agent/configs/SETUP.md
   ```

## Troubleshooting

### Issue: Configuration not loading

**Solution:**
```bash
# Check file exists
test -f .agent/configs/tasker.yml && echo "OK" || echo "Missing"

# Check file format
cat .agent/configs/tasker.yml

# Try environment variables instead
export TASKER_MODE=direct
tasker component list
```

### Issue: "Connection refused"

**Solution:**
```bash
# Verify correct mode
echo $TASKER_MODE

# Test connectivity
curl http://localhost:8888/health  # API mode
curl http://localhost:8000/health  # Database

# Check configuration file
cat .agent/configs/tasker.yml
```

### Issue: "Authentication failed"

**Solution:**
```bash
# Check credentials are correct
echo $TASKER_NEO4J_PASSWORD

# For API, check API key
echo $TASKER_API_KEY

# Try without auth (if not required)
unset TASKER_API_KEY
tasker component list
```
