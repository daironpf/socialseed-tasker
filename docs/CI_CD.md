# CI/CD Hardened Pipelines and Release Automation

## Workflows

| File | Description |
|------|-------------|
| `.github/workflows/pipeline.yml` | Main CI pipeline (lint, unit-tests, build, docker, sign, publish) |
| `.github/workflows/release.yml` | Release workflow triggered on tag push and workflow_dispatch |
| `.github/workflows/canary-deploy.yml` | Canary deployment and smoke tests |
| `.github/workflows/security-scan.yml` | Scheduled security scans |

## Secrets required (GitHub repository settings)

| Secret | Description |
|--------|-------------|
| `PYPI_API_TOKEN` | Token for publishing to PyPI |
| `DOCKERHUB_USERNAME` | DockerHub username |
| `DOCKERHUB_TOKEN` | DockerHub access token |
| `RELEASE_GPG_PRIVATE_KEY` | Base64-encoded GPG private key for signing |
| `RELEASE_GPG_PASSPHRASE` | GPG key passphrase |
| `PUBLISH_RELEASE` | Set to `1` to enable publish job |

## Integration suite (opt-in)

The `integration` job in `.github/workflows/ci.yml` runs only on manual dispatch
with `integration = true`. It provisions a disposable stack (Neo4j, PostgreSQL,
Redis, Mongo, API, board, GraphQL, Graphviz, Keycloak, Jaeger, Prometheus and
Grafana), waits for every endpoint, runs
`pytest -m "integration and not requires_chaos and not requires_treesitter"` and
dumps logs on failure. Chaos and tree-sitter groups stay manual.

The tests are grouped by prerequisite markers; see
[docs/INTEGRATION_TESTS.md](INTEGRATION_TESTS.md) for the inventory, ports,
environment variables and the local commands for each group.

## Local usage

```bash
# Run local pipeline subset
./scripts/ci/run_local_pipeline.sh

# Sign an artifact locally
export RELEASE_GPG_PRIVATE_KEY="<base64-key>"
export RELEASE_GPG_PASSPHRASE="<passphrase>"
./scripts/ci/sign_artifact.sh dist/tasker-*.whl
```

## Artifact naming and provenance

- Artifacts stored in `dist/` with deterministic names: `tasker-{tag}-{commit}.whl`
- Provenance file `artifacts/provenance-{tag}-{commit}.json` generated by CI after build

## Rollback and canary

- Canary deploys use `.github/workflows/canary-deploy.yml` and run smoke tests; failures trigger rollback job.

## Adding new jobs

1. Add job to `.github/workflows/pipeline.yml`
2. Update this documentation
3. Add corresponding smoke tests in `tests/ci/`
